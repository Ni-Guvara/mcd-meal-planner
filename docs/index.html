01它解决什么问题

麦当劳 App 只会向你推销，不会替你优化。

人多就乱

4 个人 150 块、有人不吃辣、有人吃素 —— 怎么配才既吃够又不超预算？心算永远差一口气。

省钱靠猜

单点、套餐、1+1 随心配、优惠券四条价格通道同时存在。同一份清单不同买法差几十块，而「满 40 减 10」和「8.8 折」谁更省，取决于这单构成。

热量是黑箱

套餐营养数据不公开，菜单只标单价。减脂期想吃一顿麦当劳，没人告诉你这单到底多少卡。

05架构：把「算」和「说」分开

上千套组合的枚举是纯数学问题 —— 交给大模型又慢又会算错钱，交给脚本几毫秒出解、可复现、可验算。

用户说人话  ──►  大模型理解意图（人数/预算/忌口/热量目标）
                        │
                        ▼
          麦当劳官方 MCP 实时数据（门店/菜单/价格/营养/券）
                        │
                        ▼
        求解脚本（纯本地 · 零 token · 确定性）
   忌口硬过滤 → 分档选主食 → 平替换算 → 券最优匹配 → 凑单陷阱判断
                        │
                        ▼
        calculate-price 官方核价 ──►  方案 + 总价 + 热量 + 依据
